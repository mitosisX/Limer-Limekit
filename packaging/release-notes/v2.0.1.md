## Limer 2.0.1 — now on Windows, macOS and Linux

Desktop apps in Lua, one download. Python, Qt and the Limekit framework are
inside — there is nothing else to install.

### Download

| Your computer | Download | Then |
|---|---|---|
| **Windows** 10/11, 64-bit | `Limer-2.0.1-windows.zip` | Unzip anywhere, run **`Limer.exe`** |
| **Mac** with Apple silicon (M1 and later) | `Limer-2.0.1-macos.zip` | Unzip, move **Limer** to Applications, right-click it → **Open** |
| **Mac** with an Intel chip | `Limer-2.0.1-macos-intel.zip` | The same |
| **Linux**, 64-bit | `Limer-2.0.1-linux.tar.gz` | Unpack anywhere, run **`Limer/Limer`** |

Not sure which Mac you have? Apple menu → **About This Mac**: "Chip: Apple M…" is Apple silicon; "Processor: Intel" is Intel.

### What's new since 2.0
- **macOS and Linux.** Every build is checked on its own system before it is released: it starts, runs a project, and builds an app that runs.
- **Code completion in your editor.** Limer sets up every project it opens so VS Code (with the free *Lua* extension) completes the whole Limekit API, shows each method's docs and underlines typos.
- **[Limekit for VS Code](https://marketplace.visualstudio.com/items?itemName=OmegaMsiska.limekit-vscode)** — a **▶ Run** button for your app, errors you can click to jump to the line, and `lk-` snippets.
- **Build** — leaving *Pack into a single file* unticked now really gives you a folder; nothing is left behind in your project afterwards; *Show a console window* starts unticked.
- **Inspector** — shows your widgets by their Limekit names (`ui.Button`, `ui.ListBox`), never Qt's, and hides Qt's own internal parts.

### The first time you open it
- **Windows** may say *"Windows protected your PC"*: click **More info → Run anyway**.
- **macOS** may say Limer *"cannot be opened because the developer cannot be verified"*: right-click **Limer** → **Open** → **Open**. On macOS 15 and later, if there is no Open button: **System Settings → Privacy & Security**, scroll down, **Open Anyway**.
- **Linux** needs Qt's usual system libraries, which most desktops already have. If Limer does not start, on Ubuntu/Debian:
  `sudo apt install libxcb-cursor0 libxkbcommon-x11-0 libegl1`

These warnings appear because the downloads are not code-signed yet. Apps you build show the same.

### Coming from 1.x
Limer 2.0 runs Limekit 2.0 projects; a 1.x project is recognised and Limer says so. To bring one across, see [Migrating from 1.x](https://limekit.readthedocs.io/en/latest/migrating.html).
